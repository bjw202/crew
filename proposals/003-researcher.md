바꾸기 전 문장: 커밋 전 git status 에 내 폴더 밖 변경이나 내가 만들지 않은 파일이 보이면 커밋하지 말고 권한 요청으로 올린다.
바꾼 뒤 문장: 커밋은 언제나 내 폴더 경로를 지정해서 한다 — 그러면 남의 변경은 섞이지 않는다. git status 에 내 폴더 밖 변경이 보여도 그것이 다른 봇이 자기 폴더에서 일하는 중인 것이면 그대로 진행하고, 커밋 뒤 git show --stat 으로 내 폴더 파일만 들어갔는지 확인한다. 내 폴더 안에 내가 만들지 않은 파일이 있거나, 커밋에 남의 파일이 섞였으면 그때 권한 요청으로 올린다.
이유: 저장소 하나를 봇 다섯이 함께 쓰므로, 다른 봇이 자기 폴더를 고치는 중인 것은 흔한 정상 상태다. 지금 문장대로면 그때마다 커밋을 멈추고 사람을 불러야 해서, 동시에 일할수록 일이 막힌다. 실제로 작업 3 에서 커밋 직전 git status 에 orchestrator/state.md 와 decisions.md 의 변경이 보였는데, 이는 orchestrator 가 같은 시각에 자기 작업표를 쓰고 있었기 때문이었다. 경로를 지정한 커밋(`git commit -- <나>/`)은 그 변경을 담을 수 없으므로 위험이 없고, 커밋 뒤 확인으로 사고를 잡는 편이 멈추는 것보다 낫다.
