대상 파일: crew/common/CLAUDE-common.md — "쓰기" 절의 마지막 항목
바꾸기 전 문장: 커밋 전 git status 에 내 폴더 밖 변경이나 내가 만들지 않은 파일이 보이면 커밋하지 말고 권한 요청으로 올린다.
바꾼 뒤 문장: 커밋은 언제나 내 폴더 경로를 못 박아 한다 (git add -A -- <나>/ · git commit -- <나>/). 커밋 뒤에 그 커밋에 든 파일이 내 폴더뿐인지 확인한다. 그러고도 내 폴더 안에 내가 만들지 않은 변경이 보이면 커밋하지 말고 권한 요청으로 올린다. 내 폴더 밖의 남의 파일은 다른 봇이 일하는 중이라는 뜻이므로 손대지 않고 그대로 둔다.
이유: 여러 봇이 한 저장소에서 동시에 일하면 남이 아직 커밋하지 않은 파일이 git status 에 늘 보인다. 지금 문장대로면 그 정상 상태마다 커밋이 멈추고 권한 요청이 올라가, 동시에 일할수록 사람의 손이 더 든다. 막아야 할 것은 "남의 파일이 보이는 것"이 아니라 "남의 파일이 내 커밋에 드는 것"이고, 그것은 경로를 못 박은 커밋과 커밋 뒤 확인으로 막힌다. 내 폴더 안에 낯선 변경이 있는 경우는 여전히 멈출 이유가 되므로 그 절반은 남긴다.
