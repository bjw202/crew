# orchestrator 기억 — 일하는 방법만. 과제 사실 금지. 50줄 상한.

## 명령
- python3 에 heredoc 으로 스크립트를 줄 때, 한국어가 들어가면 첫 줄에 `# -*- coding: utf-8 -*-` 를 넣는다.
  없으면 SyntaxError(Non-UTF-8) 로 통째로 실패하고, `-X utf8` 플래그로는 풀리지 않는다.
- 채팅 DB 의 messages 테이블에는 author 열이 없다. 봇 이름으로 세려면 bots 테이블을 조인한다:
  `select m.id from messages m join bots x on x.id=m.author_bot_id where x.name='orchestrator'`.

## 판정
- 검토가 "통과 + 필수 정정"을 주면 바로 통과시키지 않는다. 정정이 결론의 뜻을 바꾸는 것이면
  아직 통과하지 않은 같은 파일을 고치게 한 뒤 통과시킨다. 이것은 반려가 아니라 검토가 요구한 정정이므로
  반려 횟수를 쓰지 않는다. 통과한 뒤에는 본문을 못 고치므로 통과 처리 직전이 마지막 기회다.
- 두 봇이 서로 다른 문맥에서 같은 갈림을 같은 쪽으로 풀었으면 판정이 아니다. 진행이 막히지 않기 때문이다.
  판정으로 올리기 전에 다른 봇의 보고에 답이 이미 와 있는지 본다.
- 등급 0 은 배분한 불변 조건의 검사 결과가 보고에 실측으로 왔는지만 본다. 숫자끼리 산수가 맞는지 내가 더해 본다.

## 회차 닫기
- 회고 전에 retro.js 를 돌린다. "멘션 수가 실제와 다름"이 찍히면 채팅 DB 로 실측해 고친다 — 기억으로 세지 않는다.
- 배분 뒤 state 를 갱신하기 전에 retro.js 를 돌리면 그 어긋남이 난다. 배분과 같은 저장에서 멘션 수를 올린다.
