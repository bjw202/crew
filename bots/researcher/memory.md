# researcher 기억 — 일하는 방법만. 과제 사실 금지. 50줄 상한.

## 교차 검토
- 만든 봇의 스크립트를 다시 돌린 것은 재현이지 검토가 아니다. 원본에서 **다른 언어로 새로 구현**해 대조한다.
  같은 스크립트를 돌리면 그 스크립트의 버그가 그대로 재현된다.
- 결론이 "분석의 선택"인지 보려면 손잡이를 하나씩 돌려 표로 낸다: 창 길이 · 경계 처리 · 대상 범위 · seed.
  손잡이마다 3~6개 값을 넣고 결론이 바뀌는 자리를 찾는다. 안 바뀌면 그것이 견고함의 근거다.
- 손잡이를 돌릴 때 잣대도 같이 바꿔야 한다. 창 길이를 바꾸면서 "최소 8개" 같은 고정 문턱을 그대로 쓰면 창마다 다른 잣대가 된다.
- 무작위 검정을 검증할 때는 **내 seed 로 따로 돌린다**. 같은 seed 는 난수열까지 베끼는 것이라 독립 검증이 아니다.
  p 가 seed 만큼 다를 것을 미리 적어 두면 어긋남으로 오해받지 않는다.

## 인용 대조
- 기계 인용 검사기는 "그 행이 범위 안에 있고 무슨 내용인가"만 본다. **그 행이 문장을 뒷받침하는지는 보지 않는다.**
  "인용 어긋남 0곳"을 "주장이 근거에 닿았다"로 읽으면 안 된다.
- 특히 "~뿐이다 / ~밖에 없다 / 이것이 유일하다" 같은 전칭 문장은 인용된 행이 아니라 **반례가 있는지**로 검사한다.
  검사기는 반례를 찾지 못한다. 사람이 범위를 다시 세어야 한다.
- 문서가 스스로 선언한 범위·기간·개수는 산수로 다시 맞춰 본다. 선언과 본문 표가 어긋나는 자리가 나온다.

## 보고
- 판정은 통과·불통과·검증 불가 중 하나로 먼저 쓰고, 이유를 끝 조건 항목에 하나씩 붙인다.
- 틀린 것을 찾아도 그것이 수치·결론을 바꾸는지 따로 적는다. 바꾸지 않으면 필수 정정으로, 바꾸면 불통과로.
- 내가 새로 낸 수치는 내 근거 파일 행 번호로 가리킨다. 남의 로그 행 번호와 내 것을 다른 표기로 구분한다.

## 이 환경 (macOS, crew)
- PATH 에 /usr/bin·/bin 이 없을 수 있다. `cat`·`ls`·`git`·`python3`·`tail`·`awk` 가 command not found 로 끝난다.
  `export PATH=…` 우회와 `/usr/bin/…` 절대 경로 호출은 도구 승인 분류기가 막는다.
- 그때 쓸 수 있는 것: `node`, `find`, Read/Write/Grep/Glob 도구. 계산은 `node -e` 로 한다.
- git 이 없으면 커밋을 못 한다. 파일은 저장하고 보고의 "못 확인한 것"에 적은 뒤 권한 요청으로 올린다.
